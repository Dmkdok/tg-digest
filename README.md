# 📋 TG Digest

Ежедневный дайджест ваших Telegram-каналов и чатов: собирает сообщения за
последние 24 часа, суммаризирует их через LLM и присылает готовый разбор
прямо в Telegram — без необходимости читать сотни сообщений вручную.

Работает от вашего личного Telegram-аккаунта (через [Telethon](https://github.com/LonamiWebs/Telethon)),
поэтому подходит и для приватных чатов, куда нельзя добавить бота.

## Что делает

- Читает список каналов/чатов из `channels.txt` (публичные — по `username`,
  приватные — по числовому ID вида `-100…`).
- Забирает сообщения за последние 24 часа и чистит шум: короткие реплики без
  смысла («спасибо», «+1», эмодзи — список в `filler_words.txt`), а также
  **повторы одного и того же поста** (в лентах рекламу дублируют по 5–10 раз
  в сутки). Медиа без текста считается отдельно и видно в заголовке секции.
- Каждое сообщение попадает в промпт со временем и автором: `[09:15] Иван: …`.
  Модель видит порядок, паузы и кто что сказал, а не сплошной текст. Для
  сообщений «вчерашнего» дня печатается и дата — окно пересекает полночь.
- Большие чаты режет **по бюджету символов**, а не по числу сообщений: чанк
  набирается до `CHUNK_CHAR_BUDGET` (40 000 симв.), отдельное сообщение
  обрезается на 1 000 — так длинные посты (прайс-листы, мануалы, релиз-ноты)
  не теряют содержание, а не шумят фрагментами.
- Map-reduce: каждый чанк резюмируется отдельно, затем саммари сводятся в один
  разбор. Чат, который влезает в один чанк, обрабатывается одним вызовом.
- Выделяет сообщения с наибольшим числом реакций и **даёт ссылку `t.me`** на
  каждое, плюс ссылку на чат в заголовке секции. Модели велено копировать
  ссылки из списка, а не сочинять их.
- Текст чата передаётся как данные: корпус обёрнут в `<messages>` с явным
  указанием не выполнять инструкции из сообщений (защита от prompt injection).
- Итоговый разбор по каждому каналу — по структуре:
  - **Темы и события** — о чём вообще был день;
  - **Выводы и тезисы** — если в обсуждении родился консенсус, совет или решение;
  - **Полезное по реакциям** — что зашло аудитории и стоит внимания.
- Отправляет дайджест в Telegram, разбивая длинный текст по смысловым границам
  (лимит Telegram — 4 096 символов на сообщение).

## LLM-бэкенд

Цепочка: первый ответивший выигрывает; каждый шаг — обычный HTTP POST к
OpenAI-совместимому эндпоинту, без CLI-обёрток.

1. **DeepSeek** (`deepseek-chat`) — основной. Ключ из `.env` или окружения.
   `max_tokens` намеренно **не задаётся**: дефолт провайдера — 8K вывода, а
   искусственный потолок однажды обрезал финальный разбор на полуслове.
2. **Groq** (free tier) — запасной облачный. Промпт крупнее лимита (8K TPM на
   запрос) не отправляется и помечается как «неприменим»: это не сбой, и
   бэкенд не отключается для остальных каналов.
3. **Локальный Ollama** — последний резерв, самый медленный (на CPU-хосте
   ~4 ток/с генерации, поэтому промпты больше 6 000 символов пропускаются).

Если крупный чанк не проходит ни в один бэкенд, он автоматически делится
пополам — канал не теряется целиком.

По каждому вызову в `digest_llm.log` пишется `prompt / completion / cached /
finish`, а при `finish=length` — предупреждение: обрезка ответа не может
остаться незамеченной.

### Цена

Замер на реальном канале (~4 700 сообщений в сутки, 202 тыс. символов):
10 чанков по ~40 тыс. символов, промпты 12–14 тыс. токенов, **≈ $0.05 за
прогон** на DeepSeek — около $1.5 в месяц. Стоимость линейно зависит от
`CHUNK_CHAR_BUDGET`.

## Установка

```bash
git clone https://github.com/Dmkdok/tg-digest.git
cd tg-digest
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 1. Авторизация Telegram-аккаунта

```bash
python auth.py
```

Введите номер телефона и код из Telegram — создастся файл `session.session`
(в `.gitignore`; никогда не коммитьте его, это доступ к вашему аккаунту).

> ⚠️ Код входа не передавайте через сам Telegram — ни в переписку, ни в
> «сохранёнки», ни боту. Telegram видит код в сообщении, отправленном с вашего
> аккаунта, и блокирует вход как фишинг. Вводите код только в терминале.

### 2. Список каналов

```bash
cp channels.example.txt channels.txt
```

```
durov
some_public_chat
-1001234567890
```

### 3. Ключи LLM

Создайте `.env` рядом со скриптом (или укажите путь в `DIGEST_ENV_FILE`):

```dotenv
DEEPSEEK_API_KEY=...
GROQ_API_KEY=...
```

Скрипт читает файл сам и не перетирает уже заданные переменные окружения —
это важно для запуска из cron, где окружение родителя не наследуется.

### 4. Запуск

```bash
python fetch_digest.py
```

Скрипт отправит дайджест через `hermes send` и напечатает в stdout, сколько
сообщений ушло. Для проверки без отправки удобно вызвать сборщик напрямую:

```python
import asyncio, fetch_digest
sections = asyncio.run(fetch_digest.build_digest())
```

## Настройка через переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TG_API_ID`, `TG_API_HASH` | Telegram Desktop (публичная пара) | Свои значения — на [my.telegram.org](https://my.telegram.org) |
| `TG_SESSION_FILE` | `./session` | Путь к файлу Telethon-сессии |
| `TG_CHANNELS_FILE` | `./channels.txt` | Путь к списку каналов |
| `TG_FILLER_FILE` | `./filler_words.txt` | Путь к списку filler-слов |
| `DIGEST_ENV_FILE` | `./.env` | Файл с ключами |
| `DIGEST_HOURS_BACK` | `24` | За сколько часов собирать сообщения |
| `DEEPSEEK_API_KEY` | — | Включает DeepSeek (основной бэкенд) |
| `GROQ_API_KEY` | — | Включает Groq (запасной) |
| `OLLAMA_CHAT_URL` | `http://127.0.0.1:11434/api/chat` | Включает локальный Ollama |
| `OLLAMA_MODEL` | `qwen2.5:3b` | Модель Ollama |
| `HERMES_BIN` | `hermes` | Бинарник для доставки в Telegram |

Тонкая настройка — константы в начале `fetch_digest.py`: `CHUNK_CHAR_BUDGET`,
`MAX_MSG_LEN`, `MAX_CHUNKS_PER_CHANNEL`, `TOP_REACTED_N`.

## Блокировка сессии

Скрипт берёт эксклюзивный `flock` на `<session>.session.lock` на время чтения
Telegram. Это защита от параллельного запуска: одна авторизация не должна
слать запросы из двух соединений одновременно — Telegram отвечает
`AUTH_KEY_DUPLICATED`, причём даже когда соединения с одного IP. Второй
процесс ждёт до 5 минут, затем продолжает с предупреждением: потерять
ежедневный дайджест хуже, чем редкое перекрытие.

## Автоматизация (cron)

```cron
0 4 * * * cd /path/to/tg-digest && .venv/bin/python fetch_digest.py
```

Доставка идёт через `hermes send`, а не через stdout: cron-обёртке не нужно
(и не следует) отправлять весь вывод одним сообщением — Telegram отклонит
текст длиннее 4 096 символов.

## Структура репозитория

```
fetch_digest.py       — сбор, чистка, суммаризация, отправка
auth.py               — одноразовая авторизация Telethon
channels.example.txt  — шаблон списка каналов
filler_words.txt      — слова/фразы-пустышки для фильтрации
requirements.txt      — зависимости
```
